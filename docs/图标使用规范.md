# UeePayFrontend 图标使用规范

本文档用于约束 AI Coding Agent 和开发者在 `UeePayFrontend` 用户端项目中选择、引入、使用和维护图标的默认规则。项目主要图标来源为 View UI Plus 内置 Ionicons 和 iconfont.cn 项目图标。图标属于金融用户端界面信息表达的一部分，必须优先保证语义准确、风格一致、可访问、可维护，不得为了装饰破坏可信感和合规表达。

## 1. 图标来源优先级

优先级从高到低：

1. View UI Plus 内置 `<Icon>`：适合通用操作、方向、状态、系统动作。
2. 当前项目已接入的 iconfont.cn 字体图标：适合金融业务、卡片、认证、代理、场景化展示。
3. 当前项目已有图片或 SVG 资源：适合官方品牌 Logo、币种图标、国家/地区旗帜、产品示意图。
4. 新增 iconfont.cn 图标：仅当现有 View UI Plus 和项目 iconfont 都无法表达语义时使用。

禁止：

- 使用 emoji 作为结构性图标。
- 临时从网络复制不明来源 SVG / PNG。
- 为单个小图标引入新图标库。
- 随意混用多种风格、线宽、圆角和填充方式。

## 2. View UI Plus 图标规范

View UI Plus 图标适合：

- 返回、前进、展开、收起、刷新、搜索、关闭、复制、编辑、删除。
- loading、success、warning、error、info 等常见状态。
- 通用系统功能，如通知、设置、退出、锁定。

示例：

```vue
<Icon type="md-refresh" size="16" />
<Icon type="ios-arrow-forward" />
<Icon type="md-copy" />
<Icon type="ios-loading" class="spin-icon" />
```

要求：

- `type` 优先使用 `ios-`、`md-`、`logo-` 前缀的现有图标。
- 可点击图标必须有足够点击区域，不能只给 14px 图标绑定点击。
- loading 图标必须配合禁用态或防重复提交。
- 删除、下线、注销等危险动作必须使用明确颜色和确认文案，不只靠图标表达。

## 3. iconfont.cn 图标规范

当前项目已引入：

```text
src/assets/icons/iconfont.css
src/assets/fontsnew/iconfont.css
```

引入位置：

```text
src/App.vue
```

iconfont 适合：

- 金融业务图标：卡片、充值、提现、手续费、账单、收益。
- 认证和安全图标：证件、人脸、锁、权限、风控、数据安全。
- 官网/营销场景图标：合作、全球、跨境、服务、品牌、报表。
- 移动端底部导航或业务入口图标。

示例：

```vue
<Icon custom="iconfont icon-recharge" size="24" />
<Icon custom="iconfont icon-withdraw" size="24" />
<span class="iconfont icon-shenjizhuizong"></span>
<IconBox icon="icon-yinhangka-m" :size="26" />
```

要求：

- 使用 iconfont 时，class 必须以 `icon-` 开头。
- 页面和组件调用统一优先使用 `iconfont icon-xxx`，避免在业务代码中批量区分字体包。
- `src/assets/icons/iconfont.css` 旧包使用 `font-family: "iconfontOld"`，并在 CSS 内对旧图标类做兼容映射。
- `src/assets/fontsnew/iconfont.css` 新包使用 `font-family: "iconfont"`。
- `icon-question` 虽然两个包都有定义，但项目统一按新包处理，使用 `iconfont icon-question`。
- 配合 View UI Plus `<Icon>` 时优先使用 `custom="iconfont icon-recharge"` 或 `custom="iconfont icon-shenjizhuizong"`。
- 配合项目 `IconBox` 时直接传 `icon-xxx`。
- 不要把 iconfont 图标当作文本内容传给用户可复制字段。
- 不要使用 iconfont 表示官方品牌 Logo，品牌 Logo 应使用官方 SVG / 图片资源。

## 4. IconBox 使用规范

`IconBox` 位于：

```text
src/components/com/IconBox.vue
```

当前行为：

- `icon` 包含 `icon-` 时渲染 iconfont。
- `icon` 包含 `ios-`、`md-`、`logo-` 时渲染 View UI Plus `<Icon>`。
- 其他情况回退为 `ios-keypad`。

适用场景：

- 卡片式入口。
- 官网/合作页功能点。
- 统计卡标题图标。
- 同一组件需要同时兼容 View UI Plus 和 iconfont 的场景。

示例：

```vue
<IconBox icon="icon-fengkongxinxi" :size="26" />
<IconBox icon="md-refresh" :size="18" />
```

要求：

- 传给 `IconBox` 的 `icon` 必须是明确存在的图标名。
- 不要依赖默认 `ios-keypad` 作为正式图标。
- 新增图标使用前必须检查当前 iconfont css 是否已有对应 class。
- 若图标用于可点击区域，点击事件应绑定在外层按钮或语义容器上。

## 5. iconfont.cn 维护规范

新增 iconfont.cn 图标时必须：

- 使用团队已有 iconfont.cn 项目，不新建无关项目。
- 下载完整字体包并替换对应目录文件，保持 `iconfont.css`、`.woff2`、`.woff`、`.ttf` 一致。
- 保留已有 class 名，避免旧图标编码变化导致页面错位。
- 新图标命名要语义化，如 `icon-recharge`、`icon-risk-control`。
- 不使用含义模糊或临时命名，如 `icon-test`、`icon-1`、`icon-new`。
- 更新后搜索关键页面，确认旧图标未变形、未缺失。

当前注意事项：

- 项目存在两个 iconfont css：`src/assets/icons/iconfont.css` 使用 `font-family: "iconfontOld"`，`src/assets/fontsnew/iconfont.css` 使用 `font-family: "iconfont"`。
- 旧包图标通过 `src/assets/icons/iconfont.css` 内部映射兼容旧调用，业务代码不需要主动写 `iconfontOld`。
- 新增第三套 iconfont 时不得继续使用同名 font-family 覆盖旧字体。
- 如确需新增项目，应修改 font-family 和 class 前缀，避免冲突。
- 普通单个图标需求优先加入现有 iconfont 项目，而不是新增字体项目。

## 6. 尺寸规范

推荐尺寸：

```text
12px  表格内辅助小图标
14px  按钮内小图标、行内提示
16px  常规按钮、表单、提示
18px  工具按钮、标题辅助
20px  导航、状态提示
24px  业务操作入口、卡片按钮
26-32px  官网功能卡、较重要业务入口
40px+  上传占位、空状态、插画级图标
```

要求：

- 同一层级图标尺寸必须一致。
- 按钮内图标与文字间距保持 4-8px。
- 表格操作图标不能过小，实际点击区域建议不小于 32px；移动端建议不小于 44px。
- 不用缩放图片代替矢量图标。
- 上传、空状态等大图标可以使用图片，但必须保证清晰度和 alt / 文本说明。

## 7. 颜色规范

图标颜色统一使用 `docs/设计规范.md` 定义的当前主题语义 Token；本文档不重复维护品牌色、文字色和状态色的固定值。

要求：

- 普通图标使用正文色或辅助色。
- 主操作图标使用主色。
- 成功、警告、错误图标必须配合文字说明，不能只靠颜色表达状态。
- 危险操作图标使用错误色，但必须空间上与普通操作区分。
- 禁用态图标降低透明度并禁用点击，不要只改颜色。
- 不使用低对比浅灰图标承载关键操作。

## 8. 可访问性与交互规范

要求：

- 装饰性图标不单独承载业务信息。
- icon-only 按钮必须通过可见文本、`aria-label` 或 `aria-labelledby` 提供可访问名称；原生 `title` 只能作为补充，不能单独承担按钮名称。
- 可点击图标必须有 hover / active / disabled 状态。
- 鼠标 hover 不是唯一交互，移动端必须可点击。
- loading 图标需要有明确 loading 文案或按钮状态。
- 键盘可达的图标按钮必须保留 focus 样式。
- 状态信息不能只使用颜色和图标，必须有文字。

示例：

```vue
<Button type="default" aria-label="刷新列表" @click="refresh">
  <Icon type="md-refresh" />
  <span>刷新</span>
</Button>
```

## 9. 金融与敏感场景图标规范

高风险场景：

- 查看卡片私密信息。
- 复制密钥、复制地址、复制卡号。
- 冻结、解冻、注销、删除、下线。
- 提现、Recharge、卡片转入/转出。
- KYC/KYB 提交、认证失败、认证通过。
- 开放平台公钥、IP 白名单、Webhook、authorization。

要求：

- 危险操作图标必须配合二次确认和文字说明。
- 复制类图标不能暗示已复制成功，必须有成功反馈。
- 查看类图标用于敏感信息时必须保留权限、2FA、风控或服务端授权流程。
- 锁、盾牌、风险、认证类图标不得用于暗示“绝对安全”或“保证通过”。
- 金额、卡状态、认证状态不能只靠图标表达。

## 10. 品牌、币种、国家图标规范

品牌 Logo、币种、国家/地区旗帜不走 iconfont 优先级。

要求：

- 品牌 Logo 使用官方 SVG / 图片资源，不手动画、不用相似 iconfont 替代。
- 币种图标使用已有 `src/assets/images/currency` 资源或官方资源。
- 国家/地区旗帜使用 `public/images/state` 已有资源。
- 不改官方 Logo 比例、颜色和留白。
- 外部品牌图标用于公开页面时必须确认来源可靠。

## 11. 样式与实现规范

要求：

- 页面级图标样式使用 scoped Less。
- 不对 `.iconfont` 写全局覆盖，除非是统一主题级改动。
- 不在组件内硬编码大批 iconfont unicode 内容。
- 不直接使用 `content: "\e..."` 新增图标，优先通过 iconfont class。
- 转圈 loading 动画使用 transform，不动画 width/height/top/left。
- 图标和文本基线要对齐，不让图标上下漂移。

## 12. 审查清单

新增或修改图标前检查：

- View UI Plus 是否已有合适 `ios-`、`md-`、`logo-` 图标。
- 当前 `src/assets/icons/iconfont.css` 或 `src/assets/fontsnew/iconfont.css` 是否已有合适 `icon-xxx`。
- 图标语义是否准确，是否会误导金融结果。
- 是否和同层级图标风格、线宽、尺寸一致。
- 是否有文本说明或可访问名称。
- 是否适配移动端点击区域。
- 是否涉及敏感操作、危险操作或合规文案。
- 是否引入了新的字体冲突或覆盖旧 iconfont。

## 13. 交付要求

图标相关任务使用项目 `AGENTS.md` 的统一交付格式，并额外说明：

- 使用或新增了哪些图标，来源是 View UI Plus、现有 iconfont、项目资源还是新引入资源。
- 是否涉及敏感操作、危险操作、金融状态或合规表达。
- 是否改动 iconfont 字体文件，以及是否可能影响已有图标渲染。
