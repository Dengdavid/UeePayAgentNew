# UeePayFrontend 安全与数据处理规范

本文档是用户端敏感数据、认证信息、日志、错误展示、外部资源和数据生命周期的详细权威来源。其他文档保留业务触发和摘要，不重复定义不同的数据处理规则。

## 1. 适用范围

以下变更必须阅读本文档：

- 登录、注册、找回密码、邮箱验证和 2FA。
- KYC/KYB、证件资料、Didit 和地区限制。
- 虚拟卡、实体卡、持卡人、PAN、CVV、PIN 和卡片私密信息。
- Recharge、提现、交易、余额、费用、返现和财务流水。
- 开放平台密钥、公钥、IP 白名单、Webhook 和回调地址。
- Store 持久化、Cookie、URL 参数、日志、埋点和错误上报。
- 文件上传、下载、预览、HTML 渲染、外链、iframe 和第三方 SDK。

服务端始终是数据归属、权限、认证、风控和地区限制的最终边界。前端只能减少暴露和改善交互，不能替代服务端校验。

## 2. 数据分级

| 级别 | 示例 | 默认处理 |
| --- | --- | --- |
| Public | 公开帮助文档、公开费率说明、品牌素材 | 可以公开，但仍需保证来源和文案准确 |
| Internal | 内部枚举、非敏感配置、页面状态 | 只在业务需要范围内使用，不写入公开日志 |
| Personal | 姓名、邮箱、手机号、地址、账户资料 | 默认脱敏，限制展示、复制和持久化 |
| Sensitive | Token、OTP、证件号、KYC 文件、API key、公钥配置 | 最短生命周期、最小展示，不进入 URL、日志或持久化 Store |
| Restricted | 完整 PAN、CVV、PIN、私钥、Webhook secret | 仅在服务端授权的必要流程中临时处理，禁止持久化、埋点和错误上报 |

数据级别不因接口已经返回而降低。业务无法确定级别时，按更高一级处理并请求确认。

## 3. 数据载体边界

| 载体 | Personal | Sensitive / Restricted |
| --- | --- | --- |
| 页面 | 默认脱敏，按业务最小展示 | 默认不展示；确需查看时依赖服务端权限、明确操作和短生命周期 |
| 组件局部内存 | 仅保留当前交互需要的数据 | 仅在必要流程中临时保存，关闭、完成或失败后清理 |
| Pinia state | 仅保存跨页面确需共享的字段 | Token 不得写入；其他敏感字段原则上禁止，确需临时保存时不得 persist |
| Pinia persist | 逐字段审查 | 禁止 |
| Cookie | 仅使用项目已有明确用途 | Token 只沿用当前统一认证实现，不新增旁路 Cookie |
| localStorage / sessionStorage | 禁止保存 Personal 数据；只允许语言、界面国家、时区等明确登记的非敏感偏好 | 禁止 |
| query / params / hash | 只允许白名单化的非敏感标识 | 禁止 |
| Console / 日志 / 埋点 / 错误上报 | 脱敏后且确有诊断价值 | 禁止 |
| 剪贴板 | 用户明确触发并提示风险 | 仅业务明确允许时临时复制，不自动复制、不记录 |
| 截图 / PR / 测试文档 | 使用脱敏或模拟数据 | 禁止出现真实值 |

不得通过 Base64、URL 编码、字符串拆分或前端加密把敏感数据伪装成“可以记录”的普通数据。

`docs/多语言规范.md` 登记的国家、语言和时区仅作为界面偏好保存，不得混入账户国家、地址、KYC/KYB 地区、法律资格或其他服务端个人资料；字段语义发生变化时必须重新进行数据分级。

## 4. 展示、脱敏与复制

- 卡号、手机号、邮箱、证件号使用项目统一脱敏工具或共享组件，不在页面重复实现不一致规则。
- 完整敏感信息默认不可见；查看动作必须依赖服务端授权结果，必要时触发 2FA，并提供明确的关闭或自动隐藏机制。
- CVV、OTP、PIN、私钥和 Webhook secret 不得出现在 Toast、Modal 文案、空状态、错误详情或调试面板。
- 复制敏感信息必须由用户主动触发；复制按钮不能替代权限、认证、风控和二次确认。
- loading、失败、关闭和组件卸载时不得把上一次敏感结果残留在页面或复用状态中。
- 模拟数据只允许用于明确隔离的设计、测试或演示环境，不得在实际业务页面覆盖服务端余额、卡状态、认证结果、交易结果或操作成功状态。

## 5. 请求、认证与权限

- 业务请求优先经过 `src/api/request.js`，不得使用原始 axios 绕过 token、2FA、限流、地区限制和登出处理。
- `410`、`429`、`451`、`-100` 的具体请求行为以统一请求层和技术规范为准，业务页面不得自行改写为成功。
- 前端不得通过 `user_id`、隐藏按钮、路由 meta 或本地状态决定最终数据归属和权限。
- 重试和请求重放必须继续经过统一请求层，不得重复提交资金、卡状态或认证操作。
- 取消浏览器请求不代表服务端停止执行；资金、卡状态、认证和其他非幂等操作不得依赖前端取消实现防重复。
- GET、HEAD、OPTIONS 可以按统一请求策略处理客户端超时；POST、PUT、PATCH、DELETE 默认禁止自动重试，只有服务端已提供幂等保障且业务确认后才能显式开启。
- 请求分组和取消登记不得保存请求体、Token、OTP、PAN、CVV、证件资料或密钥。
- Token、OTP、密钥、完整证件号、PAN、CVV、PIN 和 KYC 文件地址不得进入 URL。
- 涉及资金和状态变更的请求必须保留 loading、防重复提交、失败恢复和服务端幂等边界。

## 6. 日志、错误和监控

- Console、埋点、监控和错误上报只记录定位问题所需的最小信息。
- 禁止记录请求头、完整请求体、完整响应体、Cookie、Token、OTP、PAN、CVV、证件资料、密钥和上游原始报文。
- 用户错误提示不得暴露服务端堆栈、SQL、内部路径、风控策略、权限模型或第三方密钥。
- 生产 Console 清理不能掩盖真实运行错误；引入监控前必须先定义脱敏和采样边界。
- 需要关联请求时优先使用服务端提供的非敏感 request ID，不自行拼接用户身份或敏感字段。
- 截图、Lighthouse 报告、HAR 和调试导出在写入文档或 PR 前必须检查脱敏。

## 7. HTML、外链与第三方资源

- 新增 `v-html` 或动态 HTML 前必须确认内容来源；外部或可编辑内容必须经过可靠净化，不能只依赖字符串替换。
- 外部链接使用允许的协议和来源白名单；新窗口打开时使用 `noopener noreferrer`。
- 回跳地址、回调地址和下载 URL 必须校验协议、域名和业务允许范围，防止开放重定向。
- iframe、第三方认证、支付、客服、统计和 SDK 必须说明数据发送范围、失败行为和地区影响。
- 不把 Token、用户资料或认证结果拼接到第三方 URL；确需一次性票据时由服务端生成并控制有效期。
- 第三方资源失败时不得阻塞退出、取消、错误恢复或安全提示。

## 8. 文件上传、下载与预览

- 上传前校验业务允许的类型、大小和数量；前端校验不能替代服务端校验和恶意文件检测。
- 文件名、预览地址和错误信息不得泄露本地路径、内部存储路径或长期有效签名 URL。
- KYC/KYB 和证件文件只在必要流程中短暂显示，不缓存到持久化 Store。
- 下载和预览必须使用服务端授权结果；过期或无权访问时提供安全失败状态。
- Blob URL、临时预览和对象引用在关闭或卸载时及时释放。

## 9. 生命周期与清理

- 敏感数据只保留完成当前操作所需的最短时间。
- 登出、登录失效、用户切换、2FA 取消、弹窗关闭和流程完成时清理相关临时状态。
- 轮询、定时器、事件监听和未完成请求在页面卸载时停止，避免数据跨页面残留。
- 不为“下次更方便”持久化认证材料、卡片私密信息或 KYC 文件。
- 缓存和 Store 清理不得破坏服务端事实；重新进入敏感页面时重新获取授权结果。

## 11. 修改前检查

- 涉及哪些数据级别，是否真的需要在前端获取。
- 服务端是否完成数据归属、权限、认证、风控和地区校验。
- 数据是否进入 Store、Cookie、URL、日志、剪贴板、第三方资源或错误上报。
- 是否存在完整敏感信息的展示、残留、重复请求或并发覆盖。
- 是否复用统一请求、脱敏、确认、路由和 Store 工具。
- 是否需要验证登录失效、2FA、429、451、取消、关闭和移动端场景。

## 12. 交付要求

涉及 Personal、Sensitive 或 Restricted 数据时，完成回复必须说明：

```text
Security:
- Data classification:
- Display and masking:
- Storage and lifecycle:
- Authorization boundary:
- Logging and third-party exposure:
- Validation:
- Remaining risk:
```

无法验证服务端权限或真实敏感流程时，必须明确未验证范围，不得仅凭前端隐藏状态声称安全。
