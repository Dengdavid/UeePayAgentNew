# UeePayFrontend 前端工程技术规范

本文档用于约束 AI Coding Agent 和开发者在 `UeePayFrontend` 中进行前端工程、交互和 UI 工作时的通用技术基线。详细构建、测试、设计、组件、路由、Store、图标、多语言和 GitHub 流程以 `docs/README.md` 中对应专项规范为权威来源。

## 1. 适用范围

适用于以下任务：

- 页面新增、页面改版、局部 UI 优化、响应式适配。
- 表单、表格、卡片、弹窗、筛选、分页、状态、空状态、加载态等组件改造。
- 依赖、构建配置、环境模式、应用入口、全局样式和工程工具调整。
- 金融数据、卡片信息、认证流程、提现、Recharge、账单、代理奖励、开放平台配置等业务界面。
- 公开官网、帮助中心、协议、公告、注册登录和用户中心文案。
- AI 生成实现方案、代码、检查清单、PR 描述或交付说明。

不适用于纯后端逻辑、数据库设计和服务端运维脚本。

## 2. 项目技术基线

AI 必须按当前项目实际技术栈工作，不得套用其他子项目或其他框架的写法。

- Vue 3
- Vite 5
- View UI Plus
- Pinia
- Vue Router
- vue-i18n
- axios
- js-cookie
- decimal.js
- echarts
- Less
- yarn

关键约束：

- 请求必须优先使用项目封装：`src/api/request.js`、`src/utils/api.js`。
- 请求入口、拦截器、超时重试、同组请求取消、2FA 重放和错误行为以 `docs/请求封装规范.md` 为准。
- 业务页面不得直接引入原始 axios 绕过统一错误处理、2FA、451、429、登出等流程。
- 所有业务数字计算统一使用 `decimal.js` 或项目已有 Decimal 工具，不得直接使用 JavaScript `Number` 运算；具体写法与例外遵守 `docs/decimal.js数值计算规范.md`。
- 新增用户可见文案优先进入 `src/locales` 或现有文案配置。
- 普通 UI 修改默认不运行 `yarn build`；用户明确要求构建、PR 风险等级要求，或改动高风险基础设施时才构建。

### 2.1 运行环境与版本

- 依赖版本以 `package.json` 和 `yarn.lock` 为准，使用 yarn，不混用 npm 或 pnpm 改写锁文件。
- 当前仓库尚未在 `.nvmrc`、`.node-version` 或 `packageManager` 中固定 Node.js / Yarn 版本；不能在文档中猜测版本。团队确认版本后，应在代码配置与文档中同时固化。
- 当前运行入口以 `package.json`、`vite.config.js` 和 `src/config/index.js` 为事实来源：开发端口为 `5174`，`/api` 代理到沙箱服务，`/ipapi` 代理到 `https://ipapi.co`。
- 主业务请求的 `baseURL` 固定为 `/api`。`devTest` / `buildTest` 只向 Vite 传入 `testMode`；当前该 mode 仅改变 `src/config/index.js` 暴露的绝对 API host（用于上传组件等少量调用），不会覆盖开发服务器的 `/api` 代理。不得把 `testMode` 构建或沙箱验证表述为生产验证。
- `vite.config.js` 当前仍保留若干注释形式的候选代理地址，这些只能视为待治理的历史配置，不能作为日常环境切换机制。本地、测试和生产环境后续应使用明确 mode 与环境变量，并补充不含真实密钥的 `.env.example`。
- 浏览器支持范围尚未通过 Browserslist 或产品矩阵固化；改动至少保证当前主流 Chromium、Safari 移动端和项目现有移动端逻辑可用，并如实记录未验证浏览器。

### 2.2 依赖与锁文件

- 新增依赖前先确认现有依赖或原生能力不能满足需求。
- 说明依赖用途、体积、维护状态、安全风险和替代方案。
- 不为了单一页面引入大型 UI、图标、日期、动画或状态管理库。
- 更新依赖时检查破坏性变更、构建结果、bundle 变化和关键业务回归。
- `yarn.lock` 只随明确的依赖变更提交，不因无关命令产生大范围重写。
- 安全审计结果不得包含 Token、私有仓库凭据或用户敏感信息。

### 2.3 代码质量与工程命令

当前可用工程命令以 `package.json` 和 `docs/构建发布与性能规范.md` 为准；仓库尚无 lint、单元测试、E2E、bundle analyze 或 Lighthouse CLI 脚本。

- 不得声称运行了不存在的工程命令。
- 普通修改至少执行与范围匹配的静态检查；测试分层和最低验证范围遵守 `docs/测试规范.md`。
- 修改 `AGENTS.md`、`README.md` 或 `docs/*.md` 时运行 `yarn docs:check`，校验本地链接、章节锚点、项目路径和文档中的 yarn 命令。
- 执行构建时必须遵守 `docs/构建发布与性能规范.md`，不能以退出码 0 代替风险对应的运行验收；性能专项触发时再执行性能验收。
- 后续引入 lint、测试或 CI 时应独立立项，先建立基线，避免首次接入自动改写全仓库。

### 2.4 环境配置、日志与安全

- 敏感数据分级、展示、存储、日志、外链、上传下载和生命周期的详细规则统一遵守 `docs/安全与数据处理规范.md`。
- 环境变量只保存环境差异，不保存应由服务端控制的权限或业务规则。
- 浏览器可见的前端变量不能被当作密钥；敏感配置必须留在服务端。
- 生产构建的 Console 清理策略必须与运行时监控方案一致，不能因删除日志而掩盖必要错误，也不能输出 PAN、CVV、OTP、证件资料、Token 或密钥。
- 新增 HTML 渲染、外部链接、文件下载、第三方脚本或 iframe 时，必须检查 XSS、`noopener noreferrer`、来源白名单和敏感 URL。
- 错误处理应提供恢复路径，同时避免展示服务端堆栈、SQL、上游完整报文或风控细节。

### 2.5 Vue 3 + JavaScript 代码规范

#### 2.5.1 组件结构

- Vue 单文件组件统一使用 `<script setup>` 语法糖，禁止使用 Options API。
- 样式块必须包含 `scoped` 属性，避免污染全局样式；使用 Less 时可写为 `<style lang="less" scoped>`。
- 文件内部严格按 `<script setup>` → `<template>` → `<style scoped>` 的顺序排列；样式块包含 `lang` 时仍保持在文件末尾。

#### 2.5.2 响应式 API

- 优先使用 `ref()` 声明响应式状态，尽量避免使用 `reactive()`，保持项目的响应式风格统一。
- 禁止直接解构响应式对象，例如 `const { name } = props`，避免丢失响应性。
- 需要解构响应式对象时，必须使用 `toRefs()` 或 `toRef()`。

#### 2.5.3 `<script setup>` 内部顺序

`<script setup>` 内部严格按以下顺序组织：

1. 依赖与组件导入（Import）。
2. `defineProps` 与 `defineEmits` 声明。
3. 响应式状态（`ref`）与 Store 声明。
4. 计算属性（`computed`）。
5. 事件处理方法与业务函数（Methods）。
6. 生命周期钩子（`onMounted` 等）。

#### 2.5.4 模板与逻辑

- 模板中的组件标签使用 PascalCase，例如 `<UserCard />`。
- 禁止在同一标签上同时使用 `v-if` 和 `v-for`。
- 使用 `v-for` 时必须绑定唯一的 `:key`，优先使用数据的唯一 ID，避免使用数组索引。
- 避免在 `<template>` 中编写复杂 JavaScript 逻辑；超过一层判断的逻辑必须提取到 `computed` 或函数中。
- 函数优先使用卫语句提前 `return`，代码嵌套控制在两层以内。

#### 2.5.5 注释与实现说明

- 函数上方使用 JSDoc 说明函数功能、输入参数及返回值含义。
- 关键变量定义和复杂条件判断必须附带单行中文注释；不为显而易见的代码添加重复注释。
- 生成或交付代码后，使用 3–4 句话简要说明整体设计逻辑、状态组织、主要交互与影响范围。

#### 2.5.6 数值计算

- 金额、余额、费率、比例、百分比、数量、统计、平均值、上下限、单位换算及其他业务数值的加减乘除、取模、幂、累计、比较和舍入必须使用 `decimal.js`。
- 禁止使用 `+ - * / %`、`Math.round`、`Math.floor`、`Math.ceil`、`parseFloat` 或 `Number.prototype.toFixed` 直接生成业务计算结果。
- 输入优先使用接口原始字符串；计算链中保持 `Decimal` 实例，只在展示、表单或接口提交边界使用 `toString()` 或按明确精度调用 `toFixed()`。
- 循环索引、数组位置、布尔状态码等不参与业务结果的程序控制值可以继续使用原生 `Number`；日期时间计算使用项目日期工具，不为套用 Decimal 改写日期语义。
- 完整用法、校验、舍入和示例见 [decimal.js 数值计算规范](./decimal.js数值计算规范.md)。

### 2.6 页面文件与目录结构

路由页面目录参考 `src/views/ucenter/security`，按以下结构组织：

```text
src/views/<组件名称或路由页面名称>/
├── index.vue
├── components/
│   ├── XxxModal.vue
│   └── XxxSection.vue
└── data.js
```

#### 2.6.1 页面目录名称

- 页面目录使用组件名称或路由页面名称，优先与现有路由、业务模块和相邻目录的命名保持一致。
- 不为同一页面引入第二套别名；移动或重命名已有页面目录时，必须同步检查路由和直接引用。

#### 2.6.2 `index.vue`

- `index.vue` 是路由页面入口，负责页面布局、数据加载、权限边界以及局部业务组件之间的交互编排。
- 页面入口只保留页面级职责；可以独立理解、复用或维护的弹窗和局部区域应拆入 `components/`。

#### 2.6.3 `components/`

- `components/` 存放当前业务页面使用的独立组件，例如弹窗、局部表单、独立内容区和交互区域。
- 仅服务当前页面的组件保留在页面目录内；确认被多个页面复用后，再按 `docs/组件使用规范.md` 评估是否提升为共享组件。
- 组件文件使用 PascalCase，并以业务含义命名，例如 `PasswordModal.vue`，避免使用 `Modal1.vue`、`Item.vue` 等模糊名称。

#### 2.6.4 `data.js`

- `data.js` 存放页面级公共方法、状态初始参数、枚举和配置；只被 `index.vue` 或单个局部组件使用的内容保留在使用方内部。
- 当弹窗、局部组件与 `index.vue` 需要使用同一组状态或方法时，在 `data.js` 中定义并导出，避免复制实现和默认值。
- 共享可变状态优先由 `data.js` 导出创建函数，由 `index.vue` 创建当前页面实例，再通过 props、emits 或 `v-model` 与局部组件交互，避免模块顶层单例状态在多次进入页面时残留。
- `data.js` 只服务当前页面目录，不替代 Pinia；跨页面状态和需要持久化的状态按 `docs/Store使用规范.md` 管理。

## 3. 工作入口

- 任务从项目 `AGENTS.md` 和 `docs/README.md` 进入，只读取当前领域直接相关的规范和章节。
- 上级 `../AGENTS.md` 只在跨项目、规则冲突或仓库级工作流时查阅；安全、资金、权限、认证和敏感信息底线持续适用。
- 修改前检查目标页面、路由、布局、Store、API、共享组件和当前实现，识别业务风险后做最小必要修改。
- Skill 名称、版本和可用状态以运行时为准，选择边界遵守 `docs/Skill清单与使用指南.md`。
- 浏览器验证按 `docs/测试规范.md` 的风险等级执行，构建和性能验证遵守 `docs/构建发布与性能规范.md`。

## 4. 领域规则路由

本文件只维护跨领域工程基线。设计、组件、安全、测试等详细要求由专项文档唯一负责：

| 任务领域 | 详细权威来源 |
| --- | --- |
| UI、视觉、Design Token、响应式、移动端、可访问性、图表 | `docs/设计规范.md` |
| 页面容器、表单、表格、交互状态、共享组件兼容与删除 | `docs/组件使用规范.md` |
| 图标来源、语义、资源和可访问性 | `docs/图标使用规范.md` |
| 敏感数据、脱敏、Cookie、Store、URL、日志、第三方资源 | `docs/安全与数据处理规范.md` |
| Pinia state、getter、action、persist 和状态生命周期 | `docs/Store使用规范.md` |
| 路由、meta、白名单、跳转、回退和参数 | `docs/路由规范.md` |
| 用户可见文案、Locale、格式化、RTL 和翻译质量 | `docs/多语言规范.md` |
| 静态检查、浏览器验证、风险等级和回归范围 | `docs/测试规范.md` |
| 构建、Console、Lighthouse、bundle、懒加载和性能记录 | `docs/构建发布与性能规范.md` |

跨领域任务必须同时读取所有适用的专项文档，并遵守以下共同边界：

- 当前代码、配置、主题变量和共享组件决定实现事实；文档不一致时按 `docs/文档治理与冲突处理规范.md` 处理。
- 任何 UI、交互、状态或工具优化都不得绕过服务端权限、2FA、KYC/KYB、风控、地区限制、限流和敏感数据边界。
- 专项文档中的安全规则累积生效；同一实现同时涉及多个领域时取可同时满足的交集。
- 本文件不维护组件清单、设计值、脱敏示例、响应式断点、测试步骤或业务文案副本，避免与专项文档漂移。

## 5. 交付检查

每次前端或 UI 工作完成后，统一使用项目 `AGENTS.md` 的 `Summary / Tests / Skills / Risk` 交付格式，本文件不重复维护基础模板。

如果涉及高风险页面，必须额外说明：

- 是否改变接口、字段、请求参数、权限判断或提交流程。
- 是否保留原有二次确认、脱敏、loading、防重复提交和错误处理。
- 是否需要后端配合或线上数据验证。

### 5.1 构建与性能验收记录

执行 `yarn build` 或 `yarn buildTest` 时，完整流程、数据口径、回归阈值、懒加载边界、no-edit 处理和报告模板统一遵守 `docs/构建发布与性能规范.md`；测试范围统一遵守 `docs/测试规范.md`，本文件不重复维护验收步骤。

## 6. 文档维护

当以下内容发生变化时，应同步更新本文档：

- Vue、Vite、Node、Yarn、依赖管理、环境模式、工程命令或通用工程基线发生调整。
- 工作入口、领域文档路由或统一交付规则发生调整。
- 跨领域安全或授权基线发生变化，且需要调整本文件的工程入口摘要。

主题变量、共享组件、UI、路由、Store、多语言、测试、构建、性能或 GitHub 流程的详细变化只更新对应专项文档；只有本文件的工程基线、触发条件或路由关系同时变化时才同步修改本文件。
