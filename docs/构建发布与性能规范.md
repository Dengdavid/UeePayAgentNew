# UeePayFrontend 构建发布与性能规范

本文档是项目构建、浏览器运行验收、Lighthouse、bundle 分析、懒加载整改和性能记录的详细权威来源。`AGENTS.md` 与其他文档只保留触发条件和摘要。

## 1. 适用范围

以下场景必须遵守本文档：

- 用户明确要求构建、验证、测试或完成项目。
- PR 风险等级或性能专项触发构建与性能验收。
- 修改依赖、Vite 配置、路由加载、全局样式入口、应用入口或构建模式。
- 需要评估首屏加载、chunk、CSS、图片或第三方依赖体积。

普通局部页面样式、文案和文档修改默认不自动构建；是否构建以项目 `AGENTS.md` 为准。

## 2. 当前构建能力

当前 `package.json` 提供：

```bash
yarn dev
yarn devTest
yarn build
yarn buildTest
yarn preview
yarn docs:check
```

其中 `docs:check` 是文档静态校验，其余为开发、构建和预览命令。以上是当前实现快照；实际可用命令以任务执行时的 `package.json` 为准。

当前尚未提供 `analyze`、Lighthouse CLI 或自动性能预算脚本。现阶段：

- Lighthouse 使用浏览器 DevTools 执行。
- bundle 初步分析使用 Vite 构建输出与 `dist` 文件统计。
- 如需引入 bundle 可视化、自动 Lighthouse 或 CI 性能门禁，必须单独评估依赖、配置和维护成本，不能只修改文档假装能力已经存在。

## 3. 构建与性能验收边界

执行 `yarn build` 或 `yarn buildTest` 后，必须继续完成与变更风险相称的运行验收：

```text
构建
→ 启动构建产物
→ 浏览器 Console 检查
→ 页面与资源加载检查
→ 目标页面与必要调用方回归
→ 写入验证结果
```

只有 `docs/GitHub工作流规范.md` 第 4 节列出的性能专项触发时，才追加 Lighthouse、bundle、懒加载检查、前后数据和性能记录。不得只记录“构建成功”；无法完成的步骤必须写明环境限制、原因和未验证范围。

## 4. 两阶段工作流

### 4.1 开发与验证阶段

用户明确要求构建、验证、测试或完成项目时，在当前任务授权范围内：

1. 确认目标 diff 和风险等级。
2. 运行构建并启动构建产物。
3. 按风险完成 Console、资源、目标页面和必要调用方回归。
4. 记录命令、结果、已验证页面和未覆盖范围。

只有触发性能专项时才保存改造前基线，执行 Lighthouse、bundle 和懒加载分析，并在授权允许时整改、重新构建和形成前后对比。没有安全且有效的优化项时不强行拆包，但应记录分析范围和不改原因。

### 4.2 PR no-edit 发布阶段

no-edit 的进入、退出与重新授权以 `docs/GitHub工作流规范.md` 第 3、4 节为准。本阶段只执行最终 diff 对应风险等级和性能触发项，不主动修改文件：

1. 检查最终 diff 范围。
2. 低风险变更执行静态或文档检查，不强制构建和浏览器验收。
3. 中、高、关键风险按矩阵执行构建、浏览器与必要回归。
4. 触发性能专项时确认性能记录与最终代码一致。

如果最终验证发现必须修改代码或完成懒加载整改，按 GitHub 工作流停止发布并报告 blocker。

## 5. 构建与预览

默认构建：

```bash
yarn build
yarn preview
```

测试模式：

```bash
yarn buildTest
yarn preview
```

记录以下信息：

- 构建命令与 mode。
- commit 或工作区基线。
- 构建开始与完成时间。
- 构建是否出现 warning。
- warning 是既有问题还是本次新增。
- 预览 URL 和浏览器版本。

不要把 `dist` 当作源码提交，除非仓库发布流程另有明确要求。

## 6. 浏览器运行验收

### 6.1 Console

至少检查：

- JavaScript Error。
- 未处理 Promise。
- Vue runtime warning。
- 资源 404、CORS 或加载失败。
- 重复请求、重复跳转或循环更新相关异常。
- 敏感信息是否意外输出。

Console Error、未处理 Promise 和关键资源失败原则上为阻断项。已确认无业务影响的第三方 warning 可以保留，但必须记录来源和判断依据。

生产构建可能移除部分 Console 调用，不能因此跳过开发环境或浏览器 Network 检查。

### 6.2 页面与资源加载

根据改动范围选择代表性页面，至少覆盖：

- 一个公开首屏页面。
- 一个本次直接修改页面。
- 一个受影响的共享布局或用户中心页面。
- 涉及移动端时同时检查移动端宽度。
- 涉及登录、2FA、KYC/KYB、资金或卡片时，按可用权限检查相应流程。

检查：

- 首屏是否可见且无长时间空白。
- JS、CSS、字体、图片是否成功加载。
- loading、empty、error 和重试状态是否正常。
- 路由跳转、刷新和浏览器返回是否正常。
- 接口受限时是否正确显示恢复路径，而不是伪造成功。

## 7. Lighthouse 测试

### 7.1 测试方法

- 使用构建产物而不是 HMR 开发页面。
- 改造前后使用相同 URL、浏览器、设备模式和网络条件。
- 浏览器扩展、缓存和登录态可能影响数据，报告中必须说明。
- 每个代表性页面建议运行至少 3 次，记录中位数；时间不足只能运行一次时必须注明。

### 7.2 记录指标

至少记录：

- Performance 分数。
- LCP。
- CLS。
- TBT；如有真实用户或现场数据，再记录 INP。
- 首屏主要问题与 Lighthouse 建议。

目标参考：

| 指标 | 目标 |
| --- | --- |
| Performance | 公开页移动端优先达到 80 或以上 |
| LCP | 不高于 2.5 秒 |
| CLS | 不高于 0.1 |
| TBT | 不高于 200 毫秒 |

当前页面未达到目标时，不得伪造通过。先建立真实基线，并要求本次改动不得无说明地造成明显回退；后续再通过独立性能任务逐步收敛。

## 8. Bundle 分析

至少记录：

- `dist` 总体积。
- JS、CSS、图片、字体总体积。
- 最大的 JS / CSS chunk。
- 最大静态资源。
- 新增或明显增长的依赖、页面或资源来源。

可使用当前环境已有命令读取构建产物：

```bash
du -sh dist
find dist/assets -type f -print0 | xargs -0 ls -lhS
```

不得仅比较带 hash 的文件名；应结合入口、路由、依赖来源和构建日志判断。

回归判断建议：

- 单个关键 JS / CSS 产物增长超过 10% 时必须解释。
- gzip 后增长超过 50 KB 时必须解释来源和必要性。
- Lighthouse Performance 下降超过 5 分时必须复查。
- LCP、CLS 或 TBT 回退超过 10% 时必须复查。

这些阈值用于发现回退，不等同于当前项目已经达到最终性能目标。

## 9. 懒加载与拆包

### 9.1 图片加载规则

- 项目中的图片默认必须懒加载。新增或修改原生 `<img>` 时添加 `loading="lazy"`，并优先配合 `decoding="async"`。
- 图片共享组件必须默认启用懒加载；调用方使用 `UiImg`、`ImgBox`、`FormImg`、国家旗帜等组件时，不得绕过或关闭其默认懒加载行为。
- 列表、折叠区域、Tab、弹窗和使用 `v-show` 隐藏的内容仍会创建图片节点，必须确认其中的图片已启用懒加载，避免页面初始化时集中请求全部资源。
- CSS `background-image` 不支持原生 `loading="lazy"`。业务图片、国家旗帜等需要延迟加载时，应改用保持现有尺寸、裁切和交互兼容的 `<img>`，或使用可靠的可视区域加载方案。
- 首屏关键图片如果因 LCP 或核心体验必须立即加载，只能在用户或产品明确同意后例外；交付说明必须记录例外图片、原因及验证结果。
- 修改共享图片组件时必须搜索直接调用方，并检查尺寸、圆角、`object-fit`、空值、加载失败和移动端布局是否保持兼容。

验收时不能只检查标签是否存在；应通过浏览器 Network 确认远离视口的图片未在首屏集中请求，并确认滚动进入视口后能够正常加载。

### 9.2 代码与资源拆分

优先候选：

- 非首屏路由页面。
- 仅在弹窗打开后使用的重型组件。
- ECharts、富文本、二维码、动画或大图片等非首屏资源。
- 仅特定业务流程使用的模块。
- 可按语言或页面延迟加载的资源。

禁止：

- 延迟首屏必须内容导致白屏或布局跳动。
- 为追求 chunk 数量拆出大量微小请求。
- 破坏路由恢复、登录回跳、2FA、451 或权限流程。
- 让敏感页面绕过服务端校验。
- 未测量就声称性能提升。

改造前必须确认当前任务授权允许修改并搜索调用方；改造后必须重新构建并检查重复请求、加载失败、错误边界和移动端体验。PR no-edit 阶段按第 4.2 节处理。

## 11. 风险与回退

- 路由、全局样式、请求拦截、2FA、KYC/KYB、资金、卡状态和开放平台属于高风险范围。
- 性能优化不得改变接口、权限、认证、提交参数或业务状态语义。
- 拆包造成加载失败、首屏明显退化或安全流程异常时，应回退对应优化，不用额外复杂度掩盖问题。
- 报告中必须说明无法在线验证的登录态、接口权限、网络和第三方服务限制。
