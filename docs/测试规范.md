# UeePayFrontend 测试规范

本文档定义项目的测试分层、变更风险与最低验证范围。测试结果必须可复核，不得用构建成功代替运行时验证，也不得声称运行了项目当前不存在的测试脚本。

## 1. 当前测试能力

当前可用工程命令以 `package.json` 和[构建发布与性能规范](./构建发布与性能规范.md)为准。仓库尚未提供项目级单元测试、组件测试、E2E、lint 或覆盖率脚本。因此现阶段：

- 普通修改按影响范围执行静态检查和人工验证。
- 执行构建时必须遵守[构建发布与性能规范](./构建发布与性能规范.md)。
- 不能把“缺少自动化测试”写成“测试通过”；必须说明未覆盖范围。
- 默认不新增测试文件或测试用例；只有用户明确要求时，才在当前任务中补充自动化测试案例。
- 新增测试框架、CI 或依赖属于独立工程化改造，需要明确 Issue 和验收标准。

### 1.1 验证时机

- 连续的页面、样式、文案和组件修改阶段，每轮本地调整只做必要静态检查，不重复执行浏览器验证。
- 用户明确提出 `提交PR`、`更新PR` 或 `创建PR` 后，基于最终 diff 按风险等级统一验证一次，避免修改阶段与提交阶段重复检查。
- 用户单独要求“验证 / 测试”，或问题诊断必须依赖浏览器复现时，可以提前使用浏览器；已有证据可复用，但发布前仍须确认与最终 diff 一致。
- 高风险和关键流程的验证范围仍按第 3、4 节执行，本节只调整验证时机，不降低最终验收标准。

## 2. 测试分层

### 2.1 静态检查

适用于所有文件修改：

```bash
git diff --check
yarn docs:check # 修改 AGENTS.md、README.md 或 docs/*.md 时
```

同时检查：

- 目标文件语法和导入是否正确。
- 路由、Store、组件、i18n key 是否存在。
- 是否泄露密钥、Token、PAN、CVV、OTP、证件资料。
- 是否意外修改无关文件。

当本规范的风险等级、任务验收标准或项目 `AGENTS.md` 要求浏览器验证时，静态检查不能代替浏览器运行验证；低风险文档、非用户可见注释和局部无逻辑样式按第 3 节执行即可。

### 2.2 单元测试

未来引入测试框架后，优先覆盖：

- 金额、汇率、手续费和格式化工具。
- 日期、时区、手机号、邮箱和输入校验。
- 路由参数白名单与跳转辅助函数。
- Store getter、action 和持久化白名单。
- 请求错误码映射和可纯函数化逻辑。

资金计算测试必须覆盖精度、边界值、空值、负值和异常输入。

### 2.3 组件测试

优先覆盖：

- `src/components/form` 表单组件。
- `UiPage`、表格、分页、筛选和刷新。
- 弹窗确认、loading、disabled、防重复提交。
- 空状态、错误状态和重试。
- 响应式 props、events、slots 与 `v-model` 兼容。

共享组件修改必须覆盖至少一个主要调用场景和一个边界场景。

### 2.4 浏览器冒烟测试

浏览器验证至少检查：

- 页面可加载。
- Console 无阻断错误。
- 关键资源无加载失败。
- 主操作可执行。
- loading、empty、error、disabled 正常。
- 路由跳转、刷新和返回正常。
- 移动端无关键内容溢出或遮挡。

涉及构建时，使用构建产物完成冒烟测试。

### 2.5 E2E 与业务回归

未来自动化 E2E 优先覆盖：

- 注册、登录、忘记密码、邮箱验证、登出。
- 2FA 弹窗、失败重试和原请求重放。
- 451 地区限制和 429 限流。
- KYC/KYB/Didit 认证进入、提交、结果和重新认证。
- Recharge 地址、记录和同步。
- 提现提交、确认和失败恢复。
- 虚拟卡开卡、详情、冻结、解冻、注销。
- Express 付款人、收款人、交易发起和详情。
- 开放平台 IP 白名单、回调和安全设置。

E2E 不得使用真实 PAN、CVV、OTP、证件图片、密钥或生产资金数据。

## 3. 风险等级与最低验证

| 风险 | 示例 | 最低验证 |
| --- | --- | --- |
| 低 | 文档、非用户可见注释、局部无逻辑样式 | `git diff --check`，检查目标 diff；文档变更再运行 `yarn docs:check` |
| 中 | 页面交互、表单、表格、i18n、普通 API 展示 | 静态检查 + `yarn build` + 目标页面、移动端和 Console 验证 |
| 高 | 共享组件、路由、Store、请求封装、全局样式、依赖、构建配置 | 中风险验证 + 代表性调用方、关键资源和相关回归 |
| 关键 | 资金、卡状态、KYC/KYB、2FA、权限、开放平台、敏感信息 | 高风险验证 + 关键流程回归 + 服务端边界确认 + 明确回滚方案 |

风险等级决定静态、构建、浏览器和回归范围；性能专项触发条件以 `docs/GitHub工作流规范.md` 第 4 节为准，详细执行遵守构建发布与性能规范。

## 4. 按变更类型验证

### 路由

- route name、path、meta、白名单和 direct 正确。
- 登录态、刷新、回退、详情 fallback 正常。
- query / params 不携带敏感信息。

### Store

- state、getter、action 和调用方兼容。
- persist 不新增敏感字段。
- 初始化不会重复请求或形成循环。
- 登出后敏感状态正确清理。

### 请求封装

- 成功码和网络错误处理保持一致。
- `410`、`429`、`451`、`-100` 不被绕过。
- 重试仍经过统一请求层。
- 客户端超时总请求次数不超过配置上限，默认最多 3 次。
- 取消请求不触发超时重试，旧请求不清理或覆盖新请求。
- 退避期间被同组新请求替代的旧请求不得再次发起。
- 外部 AbortController、2FA 重放和 FormData 请求保持兼容。
- 错误信息不泄露敏感内容。

### 共享组件

- 搜索全部真实调用方。
- props、events、slots、`v-model` 值类型兼容。
- 桌面端和移动端均验证。
- loading、empty、error、pagination 不回归。

### 多语言

- 按 `src/locales/set.js` 检查所有启用语言。
- key 对齐，不依赖 fallback 长期显示混合语言。
- 插值、复数、RTL 和长文本布局正确。

### 样式与设计 Token

- 不引入无作用域全局污染。
- 主题变量、View UI Plus 状态和响应式正常。
- hover、focus、disabled、loading 和减少动态效果状态可用。

## 5. 测试环境与数据

- 默认开发代理指向沙箱环境，不把沙箱结果当成生产结论。
- 测试账号、认证状态和权限必须在报告中说明，但不得记录 Token 或敏感值。
- 接口受权限或数据限制时，记录到达的页面、阻断原因和未验证范围。
- 不为了通过测试绕过登录、2FA、KYC/KYB、风控或地区限制。
- 不在 URL、截图、Console 或报告中保留完整敏感数据。

## 6. 失败处理

- 发现失败先判断是本次回归、既有问题还是环境问题。
- 不隐藏 warning、Console Error、网络失败或未验证流程。
- 不为了让测试通过而删除安全校验、错误处理或真实状态。
- 需要修改代码时回到开发阶段；进入最终 PR 发布阶段后发现问题，应停止发布并报告 blocker。

## 7. 交付补充

使用项目 `AGENTS.md` 的统一交付格式；`Tests` 额外说明静态检查、构建、浏览器页面、Console、移动端、自动化检查、既有 warning 和未验证范围。高风险任务还应说明：

- 接口、字段、权限和提交流程是否变化。
- 2FA、KYC/KYB、451、限流和登出是否保持。
- 脱敏、二次确认、防重复提交和错误恢复是否保持。
- 后端、沙箱或线上数据是否仍需配合验证。
