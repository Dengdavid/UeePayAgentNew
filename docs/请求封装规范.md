# UeePayFrontend 请求封装规范

本文档是统一请求入口、请求生命周期、超时重试、同组请求取消、2FA 重放和全局错误处理的详细权威来源。工程环境与依赖以[技术规范](./技术规范.md)为准，敏感数据与幂等边界以[安全与数据处理规范](./安全与数据处理规范.md)为准，验证范围以[测试规范](./测试规范.md)为准。

## 1. 目标与边界

统一请求层必须：

- 保持 `src/api/request.js` 为业务代码唯一稳定入口。
- 统一注入 Token、语言和时区。
- 保留 `410`、`429`、`451`、`-100` 和网络错误处理。
- `-100` 出现后取消当前会话中的其他未完成请求，避免继续触发失效权限报错。
- 允许安全查询请求在客户端超时后有限重试。
- 允许搜索、筛选和分页等调用显式声明“同组只保留最新请求”。
- 保证重试和 2FA 重放继续经过统一请求层。

统一请求层不能：

- 通过取消浏览器请求替代服务端幂等和防重复提交。
- 自动重试资金、卡状态、认证或其他非幂等操作。
- 在请求标识、日志或错误对象中复制请求体、Token、OTP、PAN、CVV、证件资料或密钥。
- 把 `410`、`429`、`451`、`-100` 改写为成功结果。

## 2. 目录与职责

```text
src/api/request.js                         对外稳定入口和全部可调请求配置
src/api/request/client.js                  创建 Axios 实例并安装拦截器
src/api/request/requestInterceptor.js      请求头、策略解析和请求登记
src/api/request/responseInterceptor.js     响应生命周期调度
src/api/request/pendingRequestManager.js   同组请求取消和逻辑请求状态
src/api/request/timeoutRetry.js            客户端超时判断与重试
src/api/request/twoFactorChallenge.js      2FA 弹窗、验证和原请求重放
src/api/request/applicationErrorHandler.js 429、451、登出和网络错误副作用
```

业务 API 继续使用：

```js
import request from './request.js'
```

业务页面不得直接导入内部模块，也不得使用原始 axios 绕过统一入口。

## 3. 请求配置契约

Axios、状态码、超时重试、2FA、取消原因和静默错误等项目级变量统一维护在 `src/api/request.js` 的 `REQUEST_CONFIG` 中。内部模块通过创建请求实例时注入该配置，不得重新声明平行默认值，也不得反向导入入口文件形成循环依赖。

请求实例创建时会校验超时时间、最大请求次数和重试延迟。`maxAttempts` 必须是大于等于 1 的整数，`delays` 必须覆盖全部重试次数且每项为非负有限数值；非法配置必须在应用启动时直接报错，不得静默降级。

需要调整请求策略时先检查：

```text
src/api/request.js
```

调用方可以通过 `requestPolicy` 调整当前请求策略：

```js
request({
  url: '/example',
  method: 'get',
  params,
  requestPolicy: {
    retryOnTimeout: true,
    maxAttempts: 3,
    takeLatestKey: 'example-list',
  },
})
```

| 配置 | 含义 | 默认规则 |
| --- | --- | --- |
| `retryOnTimeout` | 客户端超时后是否重试 | GET、HEAD、OPTIONS 开启；其他方法关闭 |
| `maxAttempts` | 包含首次请求的总请求次数 | 默认 3，范围强制限制为 1 至 3 |
| `takeLatestKey` | 同组逻辑请求只保留最新一次 | 默认空，不启用 |

`config.__requestMeta` 是统一请求层的内部状态，业务代码不得读取、修改、持久化或记录。

## 4. 请求生命周期

请求执行顺序：

```text
业务调用
→ 统一请求入口
→ 注入 Token、Accept-Language、X-Timezone
→ 解析 requestPolicy
→ 注册 takeLatest 请求
→ 发起 HTTP 请求
→ 处理取消、超时、410、429、451、-100 和网络错误
→ 完成或安全重放
→ 清理 Controller、监听器、定时器和逻辑请求状态
```

一次 HTTP attempt 结束不一定代表逻辑请求结束。超时重试和 2FA 重放必须保留同一个逻辑请求 ID，最终成功、最终失败、取消或被新请求替代后才完成清理。

## 5. 客户端超时重试

默认只识别 Axios 客户端超时：

```text
ECONNABORTED
ETIMEDOUT
```

默认不自动重试：

```text
ERR_CANCELED
HTTP 408
HTTP 504
410
429
451
-100
普通业务错误
```

`maxAttempts = 3` 表示首次请求 1 次、最多重试 2 次。当前退避时间为：

```text
第一次超时：300ms 后重试
第二次超时：800ms 后重试
第三次超时：不再重试
```

重试必须重新调用统一请求实例，并在执行前确认当前逻辑请求仍有效。已经被同组新请求替代或被用户取消的请求不得在等待后重新发起。

## 6. 同组只保留最新请求

自动使用 URL 或请求体判断重复请求可能误伤多个组件的合法并发调用，也可能让敏感参数进入全局请求表。因此统一请求层只在调用方显式提供 `takeLatestKey` 时启用：

```js
request({
  url: '/user/message',
  method: 'get',
  params,
  requestPolicy: {
    takeLatestKey: 'user-message-list',
  },
})
```

相同 `takeLatestKey` 的新逻辑请求会取消前一个未完成请求。该能力适用于搜索、筛选、分页和查询条件快速变化，不代表服务端已经停止处理旧请求。

统一请求层会为所有未完成的逻辑请求维护内部 `AbortController`；`takeLatestKey` 仅决定是否启用“同组只保留最新请求”，不再决定请求是否可被登录失效流程统一取消。

当前 `UiPage` 为每个组件实例生成独立请求组，并结合组件自己的 `AbortController` 和请求 ID 管理分页竞态。请求组不能只使用 API URL，避免相同接口的多个页面实例相互取消。

请求完成清理必须同时核对请求组、逻辑请求 ID 和 Controller，旧请求不得删除或覆盖新请求的状态。

调用方已经传入 `signal` 时，统一请求层必须保留调用方主动取消能力；内部 Controller 与外部 signal 的监听必须在请求完成后解除。

## 7. 2FA 与请求重放

- `410` 不属于客户端超时。
- 用户等待输入验证码的时间不计入 HTTP 超时。
- 同时只能存在一个全局 2FA 流程。
- 验证成功后原请求只重放一次。
- 重放请求必须继续经过统一请求实例。
- 重放再次返回 `410` 时必须拒绝，禁止循环。
- `451`、`-100`、用户取消和同组新请求替代必须终止待验证请求。
- 2FA 后的 GET 可以按请求策略处理客户端超时；非幂等 POST 默认禁止自动重试。
- 关闭、失败和完成时必须清理 Vue 实例、DOM、输入焦点和定时器。

2FA 组件使用动态导入，避免 `request → TwoFactorAuth → userApi → request` 的静态循环依赖。

## 8. 状态码与取消行为

| 状态或错误 | 统一行为 |
| --- | --- |
| `code === 1` | 返回 `response.data.data` |
| `410` | 进入 2FA；重放再次出现时拒绝 |
| `429` | 显示限流提示并静默拒绝 |
| `451` | 终止待验证请求并进入地区限制页 |
| `-100` | 取消其他未完成请求，清理登录态并跳转登录页 |
| `ERR_CANCELED` | 不重试、不显示网络错误、不跳转错误页 |
| `ERR_NETWORK` / `ERR_NETWORK_CHANGED` | 沿用统一网络错误处理 |

取消请求必须保留可识别的 `ERR_CANCELED`，并使用静默错误语义。取消结果不得结束最新请求的 loading，也不得覆盖最新请求的数据。
超时退避期间取消时必须保留实际取消原因，不得将登录失效或业务主动取消统一标记为 `take-latest`。

首个 `-100` 必须先完成当前请求的清理，再以静默取消语义终止其他未完成请求、超时重试等待和 2FA 等待。已进入响应队列的请求也不得再触发业务错误提示；后续新建请求不受永久锁定，以便用户重新登录。

`429`、`451` 和 `-100` 无论来自 HTTP 状态还是响应体业务码，都必须执行统一副作用并返回拒绝结果，禁止以 `undefined`、`false` 或其他成功值结束。登录页收到 `-100` 时可以不重复跳转，但仍必须清理失效 Token。

地区限制标记不得由其他并发成功请求自动清除。仅在用户从 `451` 页面主动重新检测时先清理旧标记；如果限制仍然存在，新的 `451` 响应会重新写入并继续停留在限制页。

## 9. 非幂等和敏感操作

以下操作默认禁止超时自动重试和 takeLatest：

- Recharge、提现和其他资金操作。
- 开卡、卡片转入转出、冻结、解冻和注销。
- KYC/KYB、证件和认证提交。
- 修改密码、邮箱、2FA 和安全设置。
- 开放平台密钥、IP 白名单和回调配置修改。

这些操作必须使用 loading、disabled、业务唯一单号、服务端幂等键和服务端防重复提交。发生超时时优先查询最终状态，不得仅凭前端取消或重新发送判断业务结果。

纯查询型 POST 只有在确认不改变服务端状态后，才能显式开启超时重试或 takeLatest。

即使接口使用 GET，只要会产生服务端状态变化，也必须显式设置 `retryOnTimeout: false`。当前消息详情和全部已读接口按此规则关闭自动重试。

## 10. 修改与验证

修改统一请求层时至少验证：

- 普通成功、业务失败和 HTTP 失败。
- 客户端超时总请求次数不超过 3。
- 取消请求不会触发超时重试。
- 同组旧请求不会覆盖或清理新请求。
- 旧请求在退避期间被替代后不会重新发起。
- 外部 AbortController 仍可用。
- `410` 成功、失败、取消、并发、超时和重放。
- `429`、`451`、`-100` 和网络异常；其中 `-100` 必须取消其他请求且不重复报错。
- FormData、JSON 字符串、普通对象和 GET 参数重放。
- 请求配置、错误提示和日志不暴露敏感信息。

验证层级、浏览器矩阵和构建要求遵守[测试规范](./测试规范.md)与[构建发布与性能规范](./构建发布与性能规范.md)。

## 11. 回滚

业务调用可以通过以下策略关闭新增行为：

```js
requestPolicy: {
  retryOnTimeout: false,
  takeLatestKey: '',
}
```

发生回归时优先关闭具体调用方策略或回退内部模块实现，保留 `src/api/request.js` 的稳定入口和现有 API 引用，不恢复业务页面直接使用原始 axios。
