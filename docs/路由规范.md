# UeePayFrontend 路由规范

本文档用于约束 AI Coding Agent 和开发者在 `UeePayFrontend` 用户端项目中新增、修改、审查路由时的默认规则。路由关系到登录态、公开访问、用户中心权限、敏感页面入口、移动端布局和浏览器标题，任何修改都必须先确认当前 `src/router/router.js` 与 `src/router/index.js` 的真实结构。

## 1. 路由职责边界

当前路由主要分为：

- `whiteRoutes`：公开页面和允许未登录访问的页面。
- `loginUnableRoutes`：登录、注册、忘记密码等登录后不应继续访问的页面。
- `ucenterRoutes`：登录后的用户中心页面。
- `agentRoutes`：用户中心内的代理商子页面。
- `pageRoutes`：挂在主布局下的单页业务页面，如卡片详情、开卡、实体卡申请。
- `errorRoutes`：403、404、451、500 和兜底路由。
- `routers`：最终注册到 Vue Router 的路由集合。

AI 修改路由时必须先判断目标页面属于哪一类，不得为了快速访问把登录后页面加入公开白名单。

## 2. 路由文件边界

关键文件：

```text
src/router/router.js    路由定义、meta、白名单、用户中心子路由
src/router/index.js     createRouter、登录态守卫、标题设置、滚动行为
src/router/settings.js  国家 / 地区限制相关辅助逻辑
src/utils/route.js      页面跳转、返回、query 处理辅助函数
```

修改要求：

- 路由定义、路由名称、`meta` 修改优先在 `src/router/router.js` 完成。
- 登录态、标题、滚动行为等全局守卫逻辑只在确有必要时修改 `src/router/index.js`。
- 地区限制逻辑不得绕过，涉及 451 的改动必须说明风险。
- 跳转辅助函数属于兼容边界，修改前必须搜索调用方。

## 3. 命名规范

路由命名应稳定、可读、可被代码精确引用。

推荐：

```text
公开页：home、card、pricing、cooperate、helpIndex
用户中心：ucenter_index、ucenter_finance、ucenter_deposit
业务详情：express_detail、ucenter_cashback_detail
代理商：ucenter_agent_rewards、ucenter_agent_admin
错误页：error_404、error_451
```

要求：

- `name` 是业务跳转和权限识别的重要键，不得随意重命名。
- 新增路由必须全局搜索是否已有同名路由。
- 用户明确给出路由名称时，必须按精确 `name` 匹配，不按页面标题猜测。
- 修改 `meta` 时只改目标路由的 `meta`，不要顺手改 path、component、redirect。
- 历史上同名路由可能出现在不同分组，修改前必须全文件搜索。

## 4. path 规范

公开页使用根路径：

```js
{
  path: "/pricing",
  name: "pricing",
}
```

用户中心子页面使用相对路径：

```js
{
  path: "recharge",
  name: "ucenter_deposit",
}
```

详情或隐藏操作页可使用相对路径、动态参数或 query：

```js
{
  path: "expressDetail/:id",
  name: "express_detail",
}
```

要求：

- `ucenterRoutes.children` 中默认使用相对 path，除非当前代码已有明确绝对路径需求。
- 不为了修复跳转而随意把相对路径改成绝对路径。
- 动态参数适合详情页强标识，如 `:id`；筛选条件、分页、时间范围优先使用 query。
- query 不得携带完整卡号、CVV、OTP、证件号、密钥、KYC 文件地址等敏感信息。

## 5. meta 规范

常见 `meta` 字段：

```js
meta: {
  title: "页面标题",
  titleKey: "i18n.key",
  hidden: true,
  direct: "ucenter_finance",
  need_auth: "allow_api",
  isApp: false,
  isAppDetail: true,
  isPhone: true,
}
```

字段规则：

- `title`：浏览器标题和菜单展示的默认标题，必须正式、清晰、合规。
- `titleKey`：多语言标题键；存在时标题优先走 i18n。
- `hidden`：隐藏在菜单或导航中的页面，常用于详情页、操作页、跳转页。
- `direct`：用于标记当前隐藏页归属哪个主页面或菜单层级。
- `need_auth`：前端展示层的功能权限标记，不是最终权限边界。
- `isApp`：移动端 / App 布局标记，默认按 `true` 处理；仅需要固定桌面宽度时显式设置为 `false`。
- `isAppDetail`：移动端 / App 详情页布局标记，修改前必须确认移动端布局调用方。
- `isPhone`：移动端相关路由标记；按用户指定 route name 精确添加，不扩大范围。

要求：

- 新增登录后详情页时，通常需要 `hidden: true` 和正确的 `direct`。
- 敏感操作页不得因为 `hidden` 就绕过认证或权限。
- `need_auth` 只能控制前端可见性，服务端仍必须做最终权限校验。
- 公开页和帮助中心文案不得使用夸大金融能力的标题。

## 6. 白名单与登录态规范

`src/router/index.js` 当前根据 token 和白名单控制访问：

- 不在白名单且未登录：跳转登录，并保存 `TOROUTENAME`。
- 未登录访问 `/certify`：在通用白名单判断前跳转首页，不保存 `TOROUTENAME`。
- 已登录访问登录、注册、忘记密码等页面：跳转首页。
- `card` 虽在公开路由中，但未登录仍会跳转登录。
- 页面标题通过 `meta.titleKey` 或 `meta.title` 设置，并拼接当前 Locale 的站点名称。

要求：

- 登录后用户中心页面不得加入 `whiteRoutes`。
- 注册、登录、忘记密码应保留在 `loginUnableRoutes`。
- 卡片、资金、认证、开放平台、安全设置等敏感页面必须依赖登录态。
- 修改登录守卫时必须验证未登录访问、已登录访问登录页、目标页回跳三类场景。
- 不得通过前端路由守卫替代服务端权限校验。

## 7. 用户中心路由规范

用户中心页面位于 `ucenterRoutes.children`，以 `/ucenter` 为父级。

新增用户中心页面时应确认：

- 是否需要菜单可见。
- 是否属于详情页或操作页。
- 是否需要 `direct` 指向主页面。
- 是否需要 `need_auth` 控制前端入口。
- 是否涉及移动端 `isApp`、`isAppDetail`。
- 是否涉及资金、卡、KYC/KYB、2FA、开放平台或敏感信息。

示例：

```js
{
  path: "example_detail",
  name: "ucenter_example_detail",
  meta: {
    title: "示例详情",
    hidden: true,
    direct: "ucenter_example",
    isAppDetail: true,
  },
  component: () => import("@/views/ucenter/example/detail.vue"),
}
```

## 8. 公开页路由规范

公开页主要服务官网展示、帮助中心、注册登录和潜在客户。

要求：

- 公开页不得请求登录后敏感接口。
- 公开页不得展示用户资产、卡信息、证件信息、密钥、私密配置。
- 公开页标题和文案必须合规，不承诺不确定金融结果。
- 帮助中心详情页可使用动态参数，但不要把敏感业务数据放进 URL。
- 公开页默认使用移动端 / App 布局；仅需要固定桌面宽度时设置 `isApp: false`。

## 9. 隐藏详情页与 direct 规范

详情页、创建页、编辑页、确认页通常不直接出现在菜单中，应使用：

```js
meta: {
  hidden: true,
  direct: "父级路由名"
}
```

如果层级归属需要多个上级，可使用数组：

```js
direct: ["ucenter_agent", "ucenter_agent_rewards"]
```

要求：

- `direct` 必须指向真实存在的路由名。
- 隐藏页返回按钮、菜单高亮、面包屑或 tabs 归属应以 `direct` 为准。
- 删除或重命名父级路由时，必须同步检查所有 `direct` 引用。
- 不要用弹窗承载主导航流程；详情页应有稳定 URL。

## 10. 跳转辅助函数规范

当前 `src/utils/route.js` 提供：

```js
toRoute(name, data = {}, type = "query", options = {})
goBack(fallback = { name: "home" })
useRouteQuery()
useRouteParams()
removeQuery(keys = null)
clearQuery()
useRoute
useRouter
```

使用要求：

- 组件内站内跳转统一优先使用命名路由和 `toRoute()`；`type` 只接受 `query` 或 `params`，非法值会回退为 `query`。
- 登录、登出、认证完成、错误页、清理一次性 query 等不应返回失效页面的流程，通过 `options.replace: true` 使用 replace 语义。
- 普通业务组件不得直接调用 `window.location.href`、`window.location.replace`、`router.push()` 或 `router.replace()` 完成站内跳转；外部链接、下载、协议文件及第三方认证、支付、客服跳转除外。
- 模板中的 `<RouterLink>` / `<router-link>` 必须使用命名路由，不拼接 path 或敏感 query。
- 回退统一使用 `goBack(fallback)`；详情页、结果页和操作页必须提供对应列表或稳定入口作为 fallback，不直接调用浏览器或 Vue Router 的 back。
- 只需一次性读取当前参数时使用 `useRouteQuery()` / `useRouteParams()`；两者返回快照。需要响应路由变化时，使用本工具导出的 `useRoute()` 配合 `computed`、`watch` 或路由更新守卫，不把快照误当成响应式状态。
- 移除部分 query 使用 `removeQuery(keys)`，该方法保留其他 query；清空全部 query 的新代码使用 `clearQuery()`。`removeQuery()` 空参数清空全部 query 只作为历史兼容行为。
- 请求拦截器、Store、路由守卫、路由配置和 `src/utils/route.js` 内部可以直接使用 router；普通组件只有现有工具无法表达复杂路由状态时才例外使用，并说明原因。
- query、params 和外部跳转地址不得携带 Token、密钥、完整证件号、PAN、CVV、OTP、KYC 文件地址等敏感信息；外部输入和接口值必须经过白名单、类型转换或编码处理。
- 工具层已处理相同 `fullPath` 的重复跳转；新增辅助能力时继续保持老调用兼容，不在业务页面重复实现同类判断。

## 11. 滚动、标题和状态保持

当前滚动行为：

- 浏览器返回时优先恢复 `savedPosition`。
- 不同 path 或 `query.id` 变化时滚动到顶部。
- 其他情况不强制滚动。

要求：

- 列表到详情再返回，应尽量保留列表滚动位置和筛选状态。
- 详情页切换 id 时应滚动到顶部。
- 页面标题必须来自 `meta.titleKey` 或 `meta.title`。
- 新增页面不能缺少 title。
- 修改滚动行为前必须检查列表、详情、tabs、query 切换场景。

## 12. 404、403、451 与兜底路由

错误路由要求：

- 未匹配路径必须进入 404。
- 权限不足使用 403，不要伪装成空数据。
- 法律或地区限制使用 451，不得用前端绕过。
- 500 页面用于系统异常，不应泄露错误堆栈、接口详情或敏感字段。

## 13. 路由变更验证清单

每次路由变更至少检查：

- 路由是否在正确分组中。
- `name` 是否唯一或是否明确处理了重复风险。
- `path` 是绝对还是相对，是否符合父级结构。
- `meta.title` 或 `meta.titleKey` 是否存在。
- 隐藏页是否设置 `hidden` 和 `direct`。
- 登录后页面是否没有进入 `whiteRoutes`。
- 敏感页面是否没有暴露敏感 query。
- 菜单高亮、返回、详情跳转、刷新后访问是否正常。
- 移动端布局标记是否符合页面性质。
- `git diff -- src/router/router.js src/router/index.js src/utils/route.js` 是否只包含预期变更。

构建触发条件以项目 `AGENTS.md` 为准，完整验收遵守 `docs/构建发布与性能规范.md`。普通路由文档或局部 `meta` 调整不默认构建，除非用户要求或改动影响全局守卫、路由加载、布局入口。
